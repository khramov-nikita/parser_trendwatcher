# Карта источников: трендвотчер (короткие видео)

## Назначение

Карта под события из [`паспорт_продукта.md`](паспорт_продукта.md): хэштеги, звуки, вирусные паттерны на **TikTok**, **Reels**, **Shorts**.

Рабочий срез для запуска: [`mvp.md`](mvp.md).

Не для мониторинга вакансий и корпоративного PR — такие URL вынесены в [приложение](#приложение-не-для-тренд-событий).

## Рамки белого контура

Допустимо:

1. **RSS**
2. **Официальный API** (ключ / OAuth / approved access)
3. **sitemap.xml**
4. **Сторонние агрегаторы** с документированной публичной RSS или API (вторичный контур)

Не входит в карту как способ сбора: разбор HTML-вёрстки, captcha, обход авторизации, scrape-акторы Creative Center / Explore.

## Статусы и ярусы

| Статус | Значение |
|---|---|
| **Проверен** | Адрес открывался ранее, ответ получен (для corp-приложения) |
| **Кандидат** | Официальный endpoint / шаблон агрегатора; рабочей пригодности для трендов ты ещё не подтвердил |

Ярусы (приоритет из паспорта): `RSS` → `API` → `sitemap.xml`.

## Что проверить тебе (кандидаты)

1. YouTube Data API — ключ, квоты, выдачу Shorts/метрик под твои запросы.  
2. Список `channel_id` для RSS seed-каналов.  
3. Instagram Graph — Business/Creator, OAuth, Public Content Access, лимиты хэштегов.  
4. TikTok Research API — статус заявки / доступность под твой use case.  
5. Агрегаторы TikTok/Reels — есть ли **публичная RSS или документированная API** и допустимый ToS (без scrape).  
6. Google Trends — доступный белый экспорт/API под EN/RU/ZH.

Критерий «Проверен» для кандидата: открыл endpoint/ленту, увидел ожидаемый машинный формат (JSON API или RSS/Atom/XML), данные относятся к тренд-сигналу (не corp-новость).

Если по адресу ничего нет / только UI без API: не включать в пайплайн; оставить в матрице как пробел.
