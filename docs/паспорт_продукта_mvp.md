# Паспорт продукта (MVP): Trendwatcher

Полная версия: [`паспорт_продукта.md`](паспорт_продукта.md).  
Детали среза и внедрения: [`mvp.md`](mvp.md).  
Источники: [`карта_источников.md`](карта_источников.md).

## 1. Продукт

Робот-пилот: следит за **публичной активностью Shorts** в заданном watchlist (seed-каналы + метрики YouTube) и раз в неделю присылает топ с пояснением.

Позиционирование MVP: **не** полный авто-топ трендов TikTok + Reels + Shorts, а запускаемый срез на белом контуре.

## 2. Ниша и платформы

| | Полный паспорт | MVP |
|---|---|---|
| Ниша | тренды коротких видео | то же |
| Платформы в авто | TikTok, Reels, Shorts | **Shorts** (ядро) |
| Reels / TikTok | равноправны | опционально: whitelist-теги (Graph) / Research API |
| Рынки/языки | EN, RU, ZH | EN, RU, ZH |
| Цель | топ хэштегов, звуков, паттернов | топ **роликов и сигналов watchlist**; хэштеги/звуки — через ручной seed, не авто-discovery |

## 3. Источники данных (MVP)

1. **RSS** — ленты seed-каналов YouTube  
2. **API** — YouTube Data API v3 (обязательно); Instagram Graph и TikTok Research — если есть доступ  
3. **sitemap.xml** — не ядро MVP  
4. **HTML** — не используем для сбора в MVP  

Ручной ввод seed (хэштеги/звуки из UI платформ) допускается; парсинг UI / captcha / обход auth — нет.  
Corp newsroom/careers — не источник трендов.

## 4. Что считается событием (MVP)

### Авто-ядро (обязательно обещать)

| № | Событие |
|---|---|
| 7 | Взрывной ролик по метрикам (Shorts) |
| 9 | Появление ролика у отслеживаемых seed-каналов |
| 16 | Высокая вовлечённость (если метрики доступны) |
| 17 | Устойчивый рост 3+ дня |

### Авто условно (только при доступе)

| № | Событие | Условие |
|---|---|---|
| 8 | Кластер копий | whitelist хэштегов/запросов + Graph и/или YT search |
| 10 | Текстовый шаблон | те же данные (caption/title) |
| 7, 9, 16, 17 | Ядро на TikTok | approved Research API |

### Полуручной seed (discovery вручную, трекинг роботом)

| № | Событие |
|---|---|
| 1–2 | Хэштег в трендах / резкий рост — после занесения в seed |
| 4–5 | Звук в трендах / рост — после seed (Shorts Charts UI → карточка) |
| 6 | Вариации трека — если видно в метаданных seed |
| 13 | Факт «из официального UI» — вручную в карточке seed |
| 3 | Кросс-хэштег — только если один seed отмечен на 2+ платформах |

## 5. Что отсекается (MVP)

1. Разовый всплеск  
2. Слишком слабый рост  
3. Малый объём  
4. Низкие абсолютные метрики  
5. Низкая вовлечённость  
6. Дубли за окно N дней  
7. Шум парсинга / пустые карточки  
8. Устаревшие записи  
9. Неполный сигнал  
10. Чужой язык/рынок (вне EN / RU / ZH)  
11. Вне разрешённых платформ MVP (ядро = Shorts; Reels/TikTok — только если включены условно)  
12. Нечего операционализировать (нет ролика / seed-тега / seed-звука / шаблона)  
13. Явный promo/ads — если видно в данных  
14. Corp-PR и вакансии — не события MVP  

**Снято для MVP:** фильтр «только одна платформа» из полного паспорта — иначе Shorts-ядро отсеется целиком.

**Пороги:** не задано (задать после первой тестовой недели).

## 6. Доставка сводки

| Параметр | Значение |
|---|---|
| Кому | Только владельцу |
| Куда | Telegram |
| Сбор | Каждый день |
| Отправка | Раз в неделю: **воскресенье, 00:00** |
| Формат | **Топ с пояснением** |
| Поля пункта | платформа; тип сигнала (ролик / хэштег-seed / звук-seed); почему в топе; ссылка или ID; язык/рынок если известен |
| Приоритет в топе | сверху — сильные Shorts по метрикам |

## 7. Когда сводка MVP полезна

1. Из топа взято в работу ≥ N пунктов  
2. По пункту ясно, что снимать или что проверить  
3. Сводка заменяет ручной обход **хотя бы YouTube Shorts** (не обязательно все три платформы)  
4. Мало «пустых» недель по ядру 7 / 9 / 16 / 17  
5. Доля мусора/дублей ниже порога  
6. Пункты свежие в заданном окне  
7. Читается за 5–10 минут  
8. Есть приоритизация  
9. В пункте достаточно полей для решения  

**N, порог мусора, окно свежести:** не задано.

## 8. Вне скоупа MVP

- авто-discovery топов хэштегов/звуков TikTok / Reels / Shorts без белого API  
- системные кросс-платформа, расхождение и миграция (3 как поток, 14, 15)  
- темы/сезонность как ядро (11, 12) — позже опционально  
- разбор кадра/видео, хуки, жесты  
- детекция накрутки, стадия «выгорания», атрибуция роста роликов к сводке  
- HTML-парсинг Creative Center / Reels Trends / Charts  

## 9. Минимум для запуска

1. Ключ YouTube Data API  
2. Список seed `channel_id` (ориентир 10–30, EN/RU/ZH)  
3. Ежедневный опрос + еженедельная сборка топа в Telegram  

Дальше по готовности: whitelist + Graph → Research → ручной seed звуков/тегов.
